# Release profile v1 — безопасный вертикальный срез

Статус: proposed.

Цель: доказать основной контракт и самые рискованные инварианты, не создавая альтернативную упрощённую архитектуру.

## Что входит

- Stateless run через ephemeral session.
- RunRequest ровно из `prompt`, `mcp`, `skills`; `prompt` в v1 — только строка.
- Один настроенный reasoning-capable model provider без routing/fallback.
- Streaming RunEvent и in-process control commands.
- Последовательный agent loop.
- Built-ins `core.terminal.exec`, `core.terminal.write`, `core.fs.apply_patch`.
- MCP tools через stdio и Streamable HTTP; resources/prompts/sampling/elicitation отложены.
- Local filesystem skills без dependencies/registry, но со snapshot/digest и progressive disclosure.
- Approval modes `on_risk`, `always`, `never`; только `single_call` scope.
- Context occupancy, compaction на 80%, цель 60%, immutable audit transcript.
- Process sandbox, workspace roots, secret refs, output redaction и artifact storage.
- Single worker; незавершённый run после process crash помечается `aborted`, side effect не повторяется.

## Что не входит в этот profile

Эти возможности остаются обязательными для целевого продукта и не должны блокироваться архитектурой v1:

- persistent sessions и user/tenant memory;
- durable recovery, pause/resume, distributed leases;
- model routing/fallback;
- child runs и parallel tool graph;
- reusable approval grants и typed human input;
- remote skill registry, signatures и dependencies;
- полные MCP resources/prompts/sampling/elicitation;
- multi-tenant service isolation;
- distributed tracing и production eval platform.

## Критерии приёмки v1

### Contract и runtime

- [ ] Запуск с `{"prompt":"Ответь: ok","mcp":[],"skills":[]}` завершается `run.completed`.
- [ ] Отсутствующее, пустое или четвёртое поле даёт `INVALID_REQUEST` до model call.
- [ ] Sequence начинается с 1, монотонна и заканчивается одним terminal event.
- [ ] Tool request проходит schema validation, risk assessment и execution именно в этом порядке.
- [ ] Несколько tools исполняются последовательно; неизвестный tool не достигает executor.
- [ ] Raw chain-of-thought отсутствует в events, logs и audit.
- [ ] Hard budget останавливает зацикливание с `BUDGET_EXCEEDED`.

### Контекст

- [ ] Ниже 80% compaction не запускается; при 80% и выше происходит до model call.
- [ ] После compaction occupancy не превышает 60%.
- [ ] Prompt, pending approval, file paths и artifact refs переживают два compaction.
- [ ] Audit сохраняет исходные segments и mapping.
- [ ] Непомещающиеся pinned data дают `CONTEXT_UNRECOVERABLE`.

### Skills и MCP

- [ ] Discovery видит только name/description; активный `SKILL.md` читается полностью; resources ленивые.
- [ ] Path traversal и symlink escape skill отклоняются.
- [ ] Изменение skill на диске не меняет snapshot run.
- [ ] stdio и Streamable HTTP проходят initialize/tool discovery.
- [ ] Namespaced collision обнаруживается до model call.
- [ ] Каждый MCP call проходит локальный risk assessment.

### Tools и human-in-the-loop

- [ ] Terminal ограничивает cwd/env/output/timeout; session процесса изолирована по run.
- [ ] Patch не пишет вне workspace и атомарен.
- [ ] Существующие пользовательские изменения не откатываются автоматически.
- [ ] Risky call не начинается до approve; arguments нельзя подменить после approval.
- [ ] Deny/timeout возвращаются модели; повторное решение даёт `APPROVAL_ALREADY_RESOLVED`.
- [ ] В `never` risky call отклоняется без ожидания, а не разрешается.

### Security и audit

- [ ] Known secrets редактируются из model context, events, logs, errors и previews.
- [ ] Prompt injection из file/MCP не меняет host policy и не выдаёт approval.
- [ ] Mutating call с неизвестным исходом не retry-ится и даёт `SIDE_EFFECT_UNKNOWN`.
- [ ] Tool calls, attempts, approvals и compactions полностью восстанавливаются из audit.
- [ ] После crash незавершённый run становится `aborted`; активный side effect не повторяется.

## Exit criteria

- Все пункты v1 проходят в CI на fake model/MCP и хотя бы на одном реальном model provider.
- Пять сквозных сценариев из исходного core loop покрыты: простой ответ, длинная задача, approved external write, denied destructive action, hostile tool output.
- Публичные schemas генерируются или проверяются из одного источника типов.
- Известные расхождения с этим profile оформлены изменением спецификации до релиза.
