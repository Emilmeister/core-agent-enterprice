# Release profile v1 — enterprise agent

Статус: release candidate; enterprise obligations pending, release gate не пройден.

Цель: корпоративный агент с общими owner UI чатами, Keycloak, caller isolation, durable ожиданиями, файлами, cron и guardrails на базе существующих A2A/runtime/memory/observability foundations. Это расширение текущего candidate, а не переописание уже выпущенного релиза.

Owner UI включает безопасное форматирование ответов Markdown/GFM и
статические Mermaid-диаграммы (ENT-AC-71); raw HTML не исполняется.
Выход завершает Keycloak SSO без автоматического повторного входа (ENT-AC-72).
Завершённые tool approval и guardrail карточки скрыты из чата, сохранённые
решения и ответы владельцев на вопросы остаются доступными (ENT-AC-73).
Owner UI включает карточки действий, состояния и разрешения, компактные per-tool
настройки, scoped file cards/panel, названия чатов и доступный composer
(ENT-AC-74–80). Технический режим и пакетное сохранение исключены.

## Что входит

- A2A server с Agent Card, send/stream/get/list/subscribe/cancel и push notifications на одном binding-е.
- Text prompt как единственный вход запроса; Streamable HTTP MCP servers и local filesystem skills объявляются конфигурацией развёртывания. Durable discovery ждёт cold start масштабированного в ноль MCP до одного общего для run настраиваемого deadline.
- Stateful A2A context/session и durable Task event log в одном worker deployment.
- Durable live steering: follow-up A2A Messages адресуются активной Task и доставляются model loop на safe boundaries без interrupt текущей операции.
- Один reasoning-capable model provider без routing/fallback, с optional deployment-controlled reasoning effort и provider default при пустом значении.
- PlatformConfig + AgentConfig + EffectiveConfig snapshot; feature/tool/MCP/skill filters работают до model context.
- KernelInstructions + настраиваемый AgentProfilePrompt с runtime enforcement включённых capabilities.
- Последовательный foreground loop и параллельные background Tasks.
- Сабагенты как A2A Tasks с hard maximum depth `2`, точными tool/MCP/skill allowlists и общим parent budget.
- Память как подсистема Core Agent с Markdown source of truth, hard 200-line rejection и revision conflicts; backend выбирает `MEMORY_STORAGE_TYPE` (`in-memory`, `postgres`).
- В подсистеме памяти: BM25 + embeddings + entity graph candidates, fusion/rerank, NER/entity resolution на каждом committed write.
- Compaction working context при 90% до 10–15%, исключая system prompt/tool schemas из threshold.
- Built-ins terminal, patch, task, delegate, memory, remote-agent send_message, ожидание времени и создание cron; artifact tools удалены; отдельного memory-MCP не существует.
- Owner HITL для конкретных calls, вопросы владельцу и guardrails решения с независимыми durable deadlines и owner-only API.
- Один Kubernetes Pod; постоянные workspace чатов и обязательный Bubblewrap/egress для Python, terminal и фоновых процессов.
- Основной образ содержит компактный набор команд для текста, файлов, структурированных данных, архивов, сети и PDF; перечень в описании terminal tool не ограничивает другие доступные команды или workspace-установки.
- Основной образ содержит закреплённые read-only packages
  `systematic-debugging`, `verification-before-completion`,
  `knowledge-synthesis`, `explore-data`, `validate-data`,
  `statistical-analysis` и `sql-queries`. Их имена и краткие descriptions всегда
  доступны модели после EffectiveConfig filtering; полный `SKILL.md` и связанные
  ресурсы раскрываются только после смыслового выбора через служебные tools.
- OTel traces/metrics/logs через OTLP, один execution trace без отдельного A2A transport trace, W3C Trace Context, async Span Links для независимой background работы, OpenInference Phoenix presentation и content-off-by-default с явным local operator opt-in.
- Durable A2A result storage, secret refs, redaction и immutable audit.
- PostgreSQL production persistence для A2A Tasks, events/checkpoints, и audit; SQLite/in-memory разрешены только tests.

## Что не входит в этот profile

Эти target capabilities остаются запланированными и не должны блокироваться v1 architecture:

- multi-provider routing/fallback;
- distributed workers/leases и crash continuation запущенного local process;
- subagent depth больше `2` и user-requested detached orphan tasks; bounded
  safety fallback для не подтвердившей cancel Task остаётся частью budget flow;
- tenant memory между A2A contexts и полный consent UI;
- remote skill registry, signatures и dependencies;
- MCP resources/prompts/sampling/elicitation;
- отдельная multi-company SaaS control plane; обязательная изоляция внешних caller-ов одной компании входит в этот profile;
- online eval platform и tail-based sampling fleet.

## Критерии приёмки v1

### A2A и tasks

- [x] Agent Card честно объявляет capabilities/version и не требует собственного расширения протокола.
- [x] `return_immediately` возвращает Task, которая продолжает работу после disconnect.
- [x] Streaming, get/subscribe и push показывают согласованную status/artifact revision.
- [ ] Background Task позволяет main agent продолжить работу; `task.wait` освобождает worker и просыпается по notification.
- [x] Cancel завершает child/process tree и переводит A2A Task в `canceled`.
- [x] Durable scheduler recovery использует один post-lock server-clock expiry-fenced worker claim, продлевает его heartbeat-ом, не затрагивает workflow с live lease, сохраняет recovery provenance при late cancel и доставляет late result/notification после distributed cancel.
- [x] Долгий model/tool и активный joined child регулярно продлевают workflow lease; durable joined parent освобождает worker/lease и возобновляется после результата child. Разрешённая длительная работа не падает с `LEASE_LOST` только из-за своей длительности.
- [ ] Follow-up Message с active `taskId` возвращает ту же Task, durable/idempotent упорядочивается и учитывается до terminal result; terminal Task отклоняет новый Message.

### Kernel и context

- [x] AgentConfig может отключить memory/terminal/delegation и отдельные tools; disabled capability отсутствует в Agent Card/model context.
- [x] AgentProfile/skill/tool output не меняют rules capability, оставленной EffectiveConfig.
- [x] Working occupancy исключает system/kernel/profile, selected tool schemas и output reserve.
- [x] Ниже 90% compaction отсутствует; при 90%+ результат занимает 10–15% working capacity.
- [ ] Prompt, task contracts, memory/file refs и актуальные semantic решения переживают повторные compaction и новые Tasks того же чата.
- [x] Крупный tool result сохраняется целиком вне active context, а модель получает bounded artifact reference и выдержку без потери immutable transcript.

### Skills

- [x] Модель всегда видит имена и краткие descriptions только effective skills,
  выбирает минимальный набор по смыслу без literal-name/slash trigger и получает
  полный `SKILL.md` только со следующего turn после `core_skill_activate`.
- [x] `core_skill_read_resource` перечисляет и читает только bounded UTF-8 файлы
  активного immutable package, отклоняет symlink/path escape и возвращает digest;
  scripts автоматически не исполняются.
- [x] Оба служебных вызова учитываются общим tool budget, возвращают recoverable
  structured failures и автоматически доступны child только для явно
  делегированных skills.
- [x] `features.skills=false` и неподдерживаемая platform capability дают пустой
  skill catalog независимо от allowlist.
- [x] После запроса активации остальные calls того же assistant response получают
  `SKILL_ACTIVATION_BOUNDARY` без dispatch и повторно выбираются только следующим
  model turn с полным `SKILL.md`.
- [x] Имена служебных skill tools зарезервированы от MCP collision, а потоковый
  текст до запроса активации не публикуется клиенту.
- [x] Runtime требует закреплённый package manifest при новом admission,
  отклоняет hot mutation, безопасно продолжает legacy active instructions без
  live package и пересчитывает base context budget до следующего model call.

### Memory

- [x] Память является подсистемой Core Agent: `core_memory_*` являются built-ins, отдельный memory-процесс и MCP-роль `memory` отсутствуют; при `CORE_AGENT_MEMORY=disabled` memory tools отсутствуют, backend не создаётся и fallback не выполняется.
- [x] `MEMORY_STORAGE_TYPE` принимает `in-memory` и `postgres` с одинаковой доменной семантикой; production с включённой памятью и `in-memory` завершается ошибкой конфигурации.
- [x] Create/update требуют предварительный hybrid search и expected revision.
- [x] Create/update с 201+ body lines отклоняется без mutation/truncation/auto-split и рекомендует несколько Markdown files.
- [x] Ошибка memory tool возвращается модели как failed tool result и не завершает run.
- [x] Отдельный explicit `core_memory_split` атомарно создаёт связанные files, каждый до 200 lines.
- [x] Commit обновляет chunks, BM25, embeddings, NER/entity resolution и graph одной revision.
- [x] Изменение файла удаляет stale entity edges; index failure не публикует staging content.
- [x] Search объединяет три candidate channels и rerank возвращает component/final scores/provenance.
- [x] Полное удаление derived indexes и rebuild из Markdown восстанавливают эквивалентный retrieval corpus.

### Сабагенты

- [x] Parent передаёт instruction, exact tools/MCP/skills, memory policy и оба положительных `budget.turns`/`budget.tool_calls`; child возвращает обычный text result.
- [x] Prompt и tool description используют balanced decision rule: делегируют полезную параллельную/изолируемую/bounded independently verifiable работу и явно исключают simple, serial, tightly coupled, duplicate и policy-bypass scope.
- [ ] Child использует один task ID в workflow, scheduler handle, task tools, notifications, logs и traces.
- [x] Child не видит capability вне EffectiveConfig/delegation allowlist; protocol lifecycle/audit не являются removable tools.
- [x] Depth `2` не видит `core_delegate`, получает protected no-delegation guidance; stale call отклоняется до создания Task.
- [x] Child получает общую память только при явно делегированных `core_memory_*` tools и наследует ту же тройку scope.
- [x] Child memory commit уведомляет parent; revision conflict не использует last-write-wins.
- [x] Execution budget удерживает последний model turn внутри общего hard limit; каждый provider/tool attempt учитывается атомарно, исчерпанные tools не dispatch-ятся и возвращают structured failures, а child/root завершается с честным `complete=false` result вместо `failed`.
- [ ] Root cancel до следующей safe boundary останавливает новые child/grandchild model/tool calls и согласованно завершает scheduler/workflow как `canceled`.

### Terminal sessions и tools

- [ ] Main/child terminal commands запускаются в разных owned PTY/process groups в пределах постоянного workspace своего чата; завершение процесса не удаляет папку чата.
- [x] Основной CLI-набор, Mike Farah `yq` и PDF-команды присутствуют в собранном образе, а краткое описание terminal tool не превращает перечень в allowlist и не обещает права `root`.
- [x] Session ownership проверяется на exec/write/read/cancel; output разных agents не смешивается.
- [ ] При использовании optional child scratch-копии она создаётся из проверенного base snapshot, patch merge проверяет base revision/conflicts; работа без копии требует координации пересекающихся записей.
- [x] S3 mount используется для durable immutable data, не как active POSIX workspace.
- [x] Secret не попадает в model/A2A/OTel/artifact.
- [x] Container требует PostgreSQL credentials/schema/readiness, переживает restart и не делает implicit in-memory fallback.
- [x] Контейнер агента работает non-root и стартует с новым или существующим writable volume без удаления данных.
- [x] Новый запрос durable ожидает transient cold start всех MCP до общего `MCP_COLD_START_TIMEOUT_SECONDS` без расхода model/tool budget, изолирует session по run, очищает stale session перед initialize, прерывает ожидание по cancel и не повторяет permanent или неоднозначную mutating ошибку.
- [x] После restart безопасный root workflow автоматически продолжает следующий lease-owner; passive subscription не запускает работу, `LEASE_LOST` не создаёт ложный A2A `failed`, а terminal reconciliation атомарно сохраняет Task и push delivery.

### OpenTelemetry и audit

- [x] OTLP получает Core spans, включая `core_agent.memory.*` для search/index/NER pipeline, в том же execution trace.
- [x] Incoming A2A call имеет один `core_agent.task.execute` trace без transport/submission trace; child продолжает parent trace, а независимая background работа связана Span Link; W3C context проходит разрешённые boundaries.
- [x] Prompt, system instructions, memory text и tool arguments/results отсутствуют по умолчанию.
- [x] При explicit content capture Phoenix показывает AGENT/LLM/TOOL spans, system prompt, полный model tool catalog, tool calls/results, provider-visible reasoning/summary в OpenInference reasoning content slot и token usage; provider-hidden/opaque reasoning и credentials отсутствуют.
- [x] Metric labels bounded; audit остаётся полным при sampling/collector outage.
- [x] Local Compose запускает version-pinned Phoenix с PostgreSQL persistence и направляет в него только поддерживаемый OTLP trace signal без 404 от metrics/logs exporters.

## Exit criteria

- Все ENT-AC-01–70 (включая ENT-AC-17a), migration checks и сохранённые foundation criteria проходят на fake model/MCP/NER/embedding adapters и одном реальном provider/embedding stack.
- Сквозной demo: AgentConfig включает выбранные tools и память; A2A Message запускает background child с тем же memory scope, child commit-ит valid Markdown, main получает notification и возвращает обычный model response, который A2A публикует как Task Artifact.
- Integration test доказывает независимые PTY/process-group cancellation main и child agents, сохранность workspace чата и корректный merge при использовании optional scratch-копий.
- Markdown links, JSON/YAML examples и public schemas проходят CI.
- Известные расхождения оформлены изменением profile до релиза.
