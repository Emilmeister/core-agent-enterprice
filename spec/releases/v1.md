# Release profile v1 — foundation slice

Статус: proposed.

Цель: реализовать основной A2A agent loop вместе с memory, background/subagent, isolation и observability foundations; ни одна из этих подсистем не откладывается как архитектурная надстройка.

## Что входит

- A2A server с Agent Card, send/stream/get/list/subscribe/cancel и push notifications на одном binding-е.
- Core extension `urn:core-agent:run-capabilities:v1`; text prompt, stdio/Streamable HTTP MCP tools и local filesystem skills.
- Stateful A2A context/session и durable Task event log в одном worker deployment.
- Один reasoning-capable model provider без routing/fallback.
- PlatformConfig + AgentConfig + EffectiveConfig snapshot; feature/tool/MCP/skill filters работают до model context.
- KernelInstructions + настраиваемый AgentProfilePrompt с runtime enforcement включённых capabilities.
- Последовательный foreground loop и параллельные background Tasks.
- Сабагенты как A2A Tasks с depth `1`, точными tool/MCP/skill allowlists и общим parent budget.
- Отдельный Memory MCP Service с Markdown source of truth, hard 200-line rejection и revision conflicts.
- В Memory Service: BM25 + embeddings + entity graph candidates, fusion/rerank, NER/entity resolution на каждом committed write.
- Compaction working context при 90% до 10–15%, исключая system prompt/tool schemas из threshold.
- Built-ins terminal, patch, task, delegate и artifact tools; memory tools приходят только из MCP.
- Approval `on_risk`/`always`/`never`, single-call scope и typed human input через A2A `input-required`.
- Один container/microVM/remote sandbox backend с отдельными host boundaries; host subprocess fallback запрещён.
- OTel traces/metrics/logs через OTLP, W3C Trace Context, async Span Links и content-off-by-default.
- Artifact storage, secret refs, redaction и immutable audit.

## Что не входит в этот profile

Эти target capabilities остаются запланированными и не должны блокироваться v1 architecture:

- multi-provider routing/fallback;
- distributed workers/leases и crash continuation запущенного sandbox process;
- subagent depth больше `1` и detached orphan tasks;
- user/tenant memory между A2A contexts и полный consent UI;
- remote skill registry, signatures и dependencies;
- MCP resources/prompts/sampling/elicitation;
- reusable approval grants;
- multi-tenant managed-service hardening;
- online eval platform и tail-based sampling fleet.

## Критерии приёмки v1

### A2A и tasks

- [ ] Agent Card честно объявляет capabilities/version; Core extension валидируется до model turn.
- [ ] `return_immediately` возвращает Task, которая продолжает работу после disconnect.
- [ ] Streaming, get/subscribe и push показывают согласованную status/artifact revision.
- [ ] Background Task позволяет main agent продолжить работу; `task.wait` освобождает worker и просыпается по notification.
- [ ] Cancel завершает child/process tree и переводит A2A Task в `canceled`.

### Kernel и context

- [ ] AgentConfig может отключить memory/terminal/delegation и отдельные tools; disabled capability отсутствует в Agent Card/model context.
- [ ] AgentProfile/skill/tool output не меняют rules capability, оставленной EffectiveConfig.
- [ ] Working occupancy исключает system/kernel/profile, selected tool schemas и output reserve.
- [ ] Ниже 90% compaction отсутствует; при 90%+ результат занимает 10–15% working capacity.
- [ ] Prompt, approval, task contracts, memory/artifact refs переживают два compaction.

### Memory

- [ ] Core не имеет MemoryStore/NER/indexes; при memory disabled не подключает Memory MCP и не делает fallback.
- [ ] Create/update требуют предварительный hybrid search и expected revision.
- [ ] Create/update с 201+ body lines отклоняется без mutation/truncation/auto-split и рекомендует несколько Markdown files.
- [ ] Отдельный explicit `memory.split` атомарно создаёт связанные files, каждый до 200 lines.
- [ ] Commit обновляет chunks, BM25, embeddings, NER/entity resolution и graph одной revision.
- [ ] Изменение файла удаляет stale entity edges; index failure не публикует staging content.
- [ ] Search объединяет три candidate channels и rerank возвращает component/final scores/provenance.
- [ ] Полное удаление derived indexes и rebuild из Markdown восстанавливают эквивалентный retrieval corpus.

### Сабагенты

- [ ] Parent передаёт instruction, exact tools/MCP/skills, memory policy, budget и result schema.
- [ ] Child не видит capability вне EffectiveConfig/delegation allowlist; protocol lifecycle/audit не являются removable tools.
- [ ] Child получает общую memory только при явной передаче того же Memory MCP namespace/tools.
- [ ] Child memory commit уведомляет parent; revision conflict не использует last-write-wins.

### Isolation и tools

- [ ] Terminal, skill scripts, stdio MCP и child commands никогда не запускаются host subprocess-ом.
- [ ] Sandbox не видит host root/runtime socket/metadata/credentials и применяет default-deny egress.
- [ ] Parent/child overlays изолированы, patch merge проверяет base revision.
- [ ] Risky call не начинается до точного approval; secret не попадает в model/A2A/OTel/artifact.

### OpenTelemetry и audit

- [ ] OTLP получает Core spans и продолженный Memory Service trace для search/index/NER pipeline.
- [ ] Background/subagent trace связан Span Link с submission; W3C context проходит разрешённые boundaries.
- [ ] Prompt, system instructions, memory text и tool arguments/results отсутствуют по умолчанию.
- [ ] Metric labels bounded; audit остаётся полным при sampling/collector outage.

## Exit criteria

- Все v1 criteria проходят на fake model/MCP/NER/embedding adapters и одном реальном provider/embedding stack.
- Сквозной demo: AgentConfig включает выбранные tools/Memory MCP; A2A Message запускает background child с тем же memory namespace, child commit-ит valid Markdown, main получает notification и отдаёт Artifact.
- Isolation integration test доказывает недоступность host filesystem/socket/metadata.
- Markdown links, JSON/YAML examples и public schemas проходят CI.
- Известные расхождения оформлены изменением profile до релиза.
